# Public Mastery Registry Summary

The private Automotive Audio Mastery Registry is the working source of truth for project IDs, feature IDs, states, primary and supporting buckets, next actions, evidence, cadence, and work history. This public summary exposes the engineering structure without publishing private daily operating records.

## Operating model

- Every retained plan has a state, a primary bucket, a next action, and either a blocker or review date.
- Each project or feature has one primary bucket so evidence is not double counted.
- Supporting buckets show cross-functional relevance.
- Backlog work is separated from the bounded Ready queue.
- Evidence records state both what an artifact demonstrates and what it does not demonstrate.
- Planned, active, access-dependent, and completed work remain explicitly separated.

## Public evidence rule

GitHub contains recruiter-facing explanations, source documents, code repositories, reports, and bounded claims. The private Registry continues to manage scheduling and detailed work history; a GitHub artifact is counted as evidence only when its method, result, limitations, and next maturation step are clear.
