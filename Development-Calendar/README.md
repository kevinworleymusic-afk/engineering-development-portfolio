**Status:** ✓ **Recorded** · ◇ **Planned**

Recorded entries use short action phrases so the calendar shows what was actually done; planned entries state the intended next action.

Repository and document additions use the date of the first relevant GitHub commit. Sessions, calls, and outreach use their recorded real-world dates. Entries describing multi-day strategy or procedure development are period-level records and do not imply that a particular file was created that day.

## Weekly-to-Daily Flow

At the beginning of each week, choose the processes or objectives for the relevant categories. Each scheduled item will appear in its day cell using the category marker, linked label, status, and a very short process description:

[🟦 **Critical Listening**](Areas/critical-listening.md)<br>◇ EQ + compression warmup

Only scheduled categories appear on a given day. Multiple categories are separated into their own marked lines. The category opens its pathway, while completed work can link onward to the detailed calendar, daily log, or project evidence. Unplanned future dates remain date-only.

Use the [populated pathway plans](Plans/) to review the objectives behind recorded calendar work, and the shared [monthly and weekly templates](Templates/) to plan future cycles. Non-listening evidence remains in its project, document, calendar, or contact record.
